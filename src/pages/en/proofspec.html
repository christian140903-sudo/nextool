proofspec · executable evidence contracts

Claims are cheap. Make them executable.

proofspec turns the important statements in a README, release, product page or agent completion message into versioned checks with evidence policies, claim dependencies, receipts and a CI gate.

Install from source only

The npm package named proofspec belongs to a different project. Do not run npx proofspec; clone the repository instead.

git clone https://github.com/christian140903-sudo/proofspec

How it works

  1. Specify the narrow claim in proofspec.json: statement, severity, evidence policy, limitations, dependencies.
  2. Observe through bounded checks — file, public HTTP, Git, npm or manual — using postcondition-mcp's constrained verifiers.
  3. Resolve the claim graph: unverified dependencies block the claims that rest on them.
  4. Ship with receipts: CI fails when required claims need attention; reports go to reviewers.

Evidence policies

  • all — every check matters; one violation fails, an unresolved check keeps the claim unknown.
  • any — one satisfied observation verifies; otherwise the claim stays unknown.
  • at_least(n) — verify at the threshold, stay unknown while it could still be reached, fail only when it cannot.

Reports: JSON, Markdown, standalone HTML, Mermaid claim graph and SARIF.

What it does not do

  • A satisfied verifier proves only its configured observation, not the broadest reading of the sentence.
  • No arbitrary shell commands, credential headers or action execution.
  • Manual evidence stays unknown; an agent's own statement is not external proof.
  • The local receipt chain detects changes but is not a signed transparency log.
