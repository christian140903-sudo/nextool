postcondition-mcp · outcome verification for AI agents

The tool returned success. Did the world change?

postcondition-mcp checks whether the world changed, not whether the agent said so. It declares the intended result, observes the outside world through constrained read-only verifiers and returns a verdict: satisfied, violated or unknown.

npx -y postcondition-mcp serve

How it works

  1. Declare the outcome: a concrete result, with a subject and, if needed, a deadline.
  2. Act with any tool. postcondition-mcp is not another orchestrator; your existing tool, CI job, script or person does the work.
  3. Observe independently: a narrow verifier reads file, HTTP, Git or npm state without running arbitrary shell commands.
  4. Report the verdict — satisfied, violated or unknown — with evidence class, digest, timestamp and a link to the previous receipt.

Verifiers

  • File: existence, absence, size, SHA-256, contained text, JSON-pointer equality.
  • HTTP: GET only; status, text and JSON values with redirect, timeout, size and private-network guards.
  • Git: branch, clean tree, HEAD, tag and locally fetched remote-tracking state, through fixed argument sets.
  • npm: published versions and dist-tags from the public registry API.
  • Manual: statements by a person or an agent stay labelled as attestation and are never upgraded to external proof.

Evidence classes

ClassMeaning
externally_observedA remote HTTP or npm endpoint was read independently.
configured_verifierA constrained local file or Git check ran.
manual_attestationA person supplied the result.
self_attestationAn agent supplied its own result.

What it does not do

  • No arbitrary shell verifier, no action execution, no account, no telemetry, no required cloud service.
  • HTTP is GET-only and blocks loopback, private, link-local and reserved targets by default.
  • The local hash chain detects changes but is not a signed notarisation and gives no non-repudiation.
  • Git checks read locally fetched tracking refs; they do not contact or change the remote.
  • A young project, built in one evening, with no external users so far.
