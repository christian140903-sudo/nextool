behaviorlock · drift gate for skills and agents

Upgrade the model. See what changed in what the agent does.

behaviorlock compares portable before-and-after traces against deterministic contracts for the behaviour people depend on: tool use, permissions, output structure, outcomes, ranks, sets, sequences and bounded metrics. The result is compatible, drifted or unknown — without a judge model.

How it works

  1. Record a baseline: scenario status and narrow derived observations from the currently approved agent.
  2. Change anything — model, prompt, memory, policy, tools — and run the same scenarios.
  3. Contract what must stay stable or improve, using JSON pointers and deterministic matchers.
  4. Gate on the status: compatible, drifted or unknown, exported to CI and review formats.

Deterministic matchers

  • exists, equals, allowlist — presence, exact structure, approved values in the candidate.
  • same, contains — structural equality with the baseline or required membership.
  • set_same, sequence_same — decide whether order and duplicates are behaviour or detail.
  • number_delta — bound absolute and relative drift without turning one trace pair into a benchmark claim.
  • rank_not_lower — decisions must stay equal or improve under an explicit order.
  • Missing baselines and undefined relationships stay unknown instead of passing.

Reports: JSON, Markdown, standalone HTML, SARIF and JUnit.

What it does not do

  • It detects drift; it does not prevent it.
  • No model calls, no provider keys, no arbitrary shell execution and no network requests in the comparison.
  • Traces are trusted inputs; behaviorlock does not authenticate who produced them.
  • A passing gate covers only the declared scenarios and selectors. Weak coverage creates false confidence.
  • Behaviour fingerprints are content digests, not signatures. Trace values can appear in reports — record redacted observations, not private conversations.
