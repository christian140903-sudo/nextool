I direct AI coding agents to software that passes its tests and is shipped. An MCP memory server on npm and small verification tools for agents. One checks whether an agent really did what it reports, one whether its behaviour changed after a model switch. I have been building with Claude Code since February 2026.

I do not come from computer science: I sold, advised and dispatched — jobs where you explain technical things to non-experts every day. My first months were mass production without checks; since July I build differently, with relapses into September.

The biggest lesson came from measuring. In August a system prompt I had built seemed to show a large effect on a public benchmark. An adversarial review round of my own agents — following a rule I had set three days earlier — found two flaws in my setup the same day, only one of them fixable. I withdrew the number before it left the project. Since then I require a placebo arm and test the grader as hard as the candidate.

That is what I want to bring to a team as an employee: directing agents — and knowing when not to trust them.

Principles

  • Verify, don't trust the report. Evidence: postcondition-mcp checks the state of the world, not the success message.
  • Every measured number with a source. Evidence: every test count and measured number on this site is listed with its source and verification date in facts.json; a linter lets none through without one.
  • Withdraw what does not hold. Evidence: the case study.
  • State the limits. Evidence: every project on the projects page states what it does not do.
